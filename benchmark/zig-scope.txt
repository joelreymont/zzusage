zzusage Zig benchmark scope

Pinned input is the 1117-line src/main.zig in the immutable zzusage-9e060d9a767789ab6aaeb8739464bfb70da94b3e archive. It scans local Claude JSONL files and uses a compiled pricing table. It has no HTTP request code. build.zig.zon names vaxis, but src/main.zig does not import it and direct build-exe uses no dependency fetch.

Full lane: copied upstream source with Zig 0.17 process-argument, HOME environment, Io.Dir read/walk, streaming stdout, SafeAllocator, and ArrayList-empty initialization adaptations. Commands and presentation remain: daily (default), weekly, monthly, sessions, blocks, statusline, help. weekly and blocks intentionally route to the original daily aggregator/output. Original parser, pricing, aggregation, and JSON format are retained.

The original help path ignores a failed stdout write. Its Zig 0.17 streaming-writer adaptation catches both the write and flush errors, preserving a zero exit status when stdout is closed. Report writers still propagate write errors.

Two upstream memory-ownership faults surfaced under 0.17 SafeAllocator:
1. In the serial scan path (<10 JSONL files), events are appended with string_arena but CollectResult.deinit freed the event list with the general allocator. The serial CollectResult now records string_arena as the list allocator. This removes an invalid free without changing parsed events.
2. Report aggregation allocates keys, Row/SessionRow pointers, and maps for one command without individually freeing all of them. Both lanes now pass a command-lifetime arena to the existing report functions and release it after output. This removes leak diagnostics; row construction, sorting, totals, and output are unchanged. This is an ownership repair applied identically to full and subset, not allocator tuning for size.

The Zig 0.17 Walker.deinit implementation releases its buffers but does not close still-stacked descendant directory handles after a walk error. The full lane now leaves each remaining stack entry before deinit; Walker.leave closes descendants but leaves the base directory for its existing defer. A synthetic low-file-descriptor regression covers repeated unreadable nested roots followed by a valid root.

JSON-only lane: retains the full lane's scanner, parser, compiled pricing, aggregation, and JSON serializers. It removes ANSI/table formatting and text report branches, and keeps daily (default), weekly, monthly, sessions, blocks, and statusline. All report invocations require --json. Without it, the process exits 1 and writes exactly "This benchmark supports --json reports only\n" to stderr. --help exits 0 with one Usage line. JSON reports additionally require at least one explicit --data-dir, refusing before scanning with "zzusage-json: --data-dir is required\n". This removes HOME fallback only from the JSON subset. --order consumes its following value but remains ignored, matching the full source. Other argument behavior remains inherited; do not treat the simple usage line as a strict parser.

Synthetic smoke: one-file path exercises serial scan; twelve-file path exercises threaded work stealing. Every scan used explicit --data-dir. Across all four binaries, default/daily/weekly/monthly/sessions/blocks/statusline/+02:00 JSON outputs parsed equal with empty stderr; JSON-only refusal/help and full text reports also passed. The threaded session report records the project associated with whichever event for a shared session ID reaches aggregation first; this behavior is inherited and may vary with scheduling. The fixture has shared IDs across projects, so its project label is not a stable semantic claim.

The full reference opens each file and reads chunks through EOF, then probes one extra byte after 512 MiB. The pinned Zig 0.15.2 reader includes bytes appended after open and permits exactly 512 MiB. Zig 0.17's convenient allocating file reader both rejects a reached limit and uses a cached file size that can truncate a growing log. The explicit read loop preserves the original inclusive cap and read-through-EOF behavior. Synthetic cap-minus-one, exact-cap, and cap-plus-one fixtures verify the boundary; the concurrent append case checks initial-event retention without claiming a deterministic append count.
